## 已确定（2026-11-02）

- **先后顺序**（Eric 确认）：① 运行时逐页巡检占位入口（含管理后台），运行确认 Media Session → ② 数据库升级与恢复（第一次部署后迁移即为已发布，须在部署前完成）→ ③ 稳定性与性能实测，共用同一份合成大曲库 → ④ 部署：Dockerfile 与 CI、打 tag 构建镜像、改 dotfiles、真实 Authelia 下登录与退出；部署后用阶段 1 遗留的文件夹拖放上传导入真实曲库。
- **大曲库规模**（Eric 确认）：合成 10,000 首歌、2,000 张专辑、1,000 位艺术家、20 个歌单（每个 500 首），音频软链接到同一批真实文件。
- **视觉欠账**（Eric 决定）：首版不再严格要求。阶段 2 未采集的播放器样式切换与展开动画过程不补采；开发中 Eric 没有看出问题，部署后实际使用中遇到问题再处理。
- **性能预算**：部署环境（only）与开发机性能相近，预算以开发机实测为准。
- **镜像与版本**：首发 `1.0.0`，镜像只构建 `linux/amd64`。
- **部署**：新版直接替换 homelab 上的旧版 Sonora（`ghcr.io/ericwvi/sonora:0.5.0`，Postgres、forward_auth）。旧版完全不管：不迁移数据，不兼容其配置与历史。dotfiles 中的 compose、Caddyfile 等由 Claude 在本地修改，Eric 部署。
- **数据库升级与恢复**（Eric 决定）：1.0.0 是全新部署，服务器上原有的挂载数据全部清空，不考虑旧数据。之后的升级只追加迁移；不做自动备份，升级前由 Eric 手动备份数据卷，恢复办法写入部署说明。
