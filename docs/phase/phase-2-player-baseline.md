### 复刻范围

- **播放器严格复刻**，以截图对照验收：全屏播放器（封面、歌词、背景、控制栏及其各种模式与背景样式）、底部播放栏、播放队列抽屉。
- **SPlayer 所有视觉相关代码都复刻**：全局主题（明暗、主题色、封面动态取色）、Naive UI 主题覆盖、全局样式、组件样式、动效、歌词样式设置项、播放器外观设置项。

### 歌词

- 支持逐字歌词，歌词全部由 Eric 经管理后台上传，不接外部歌词源，不支持 YRC、QRC。
- 服务端保存歌词原文与格式标记 `lrc` / `ttml`；播放端复用 SPlayer 的解析代码（[parseLrc.ts](../../reference/SPlayer/src/utils/lyric/parseLrc.ts)、[lyricParser.ts](../../reference/SPlayer/src/utils/lyric/lyricParser.ts)）与 AMLL 的 `parseTTML` 解析，用 AMLL 渲染。
- LRC 的普通、逐字、增强型（ESLyric）由播放端按 SPlayer 的规则识别；相同时间戳的第二、三行为翻译与音译。TTML 内嵌翻译、音译与背景人声。每首歌一份歌词。
- 管理后台接受 `.lrc` 与 `.ttml`，文件夹上传时匹配同名外置文件；音频内嵌歌词按 LRC 处理。

### 播放行为

- 最近播放：播放超过 min(30 秒, 歌曲时长的一半) 才记录。
- 播放队列与播放位置保存在浏览器中；跨设备接续以后再考虑。
- 播放模式：顺序、列表循环、单曲循环、随机。
- 点击列表的“播放”：专辑、歌单、我喜欢、最近播放把整个列表放入队列；全部歌曲与搜索结果只放入已经加载的部分。
- 播放失败自动跳过，最多连续 3 首，之后停止并提示错误。

### 0.3 Chrome 音频实验

实验脚本：[scripts/experiments/chrome-audio.mjs](../../scripts/experiments/chrome-audio.mjs)。脚本启动一个使用空数据的临时 Sonora 开发实例，经管理 API 上传样本，再从播放端 API 播放，测的是真实的 Range 实现与 Content-Type。播放链路与 SPlayer 相同：`HTMLAudioElement`（`crossOrigin = "anonymous"`，`preload` 保持默认 `auto`）→ `MediaElementSource` → 10 段 peaking 滤波 → 分析器 → 输出。元素播放限速到 2 Mbit/s，让拖动时文件尚未下载完。结果在 `.local/experiments/chrome-audio/`。

- [x] 用受控样本验证（2026-10-25，Playwright Chromium 153）。样本：MP3（CBR、VBR、无标签）、FLAC、M4A（AAC）、OGG Vorbis、Opus 各一个测试样本，曲库中的 216 秒 MP3（320 kbps，627 KB 内嵌封面）、286 秒 OGG、ID3 标签只有 11 KB 的 286 秒 MP3，以及一份中间清零 64 KiB 的 MP3。
  - **解码与播放**：全部格式都能取得元数据、经 Web Audio 链路播放（分析器有信号）并完成 `decodeAudioData`，时长与服务端记录一致（误差在 30 毫秒内）。M4A 在这个 Chromium 上也能解 AAC。`canPlayType` 对 `audio/mp4`、`audio/ogg` 返回 `maybe`，因为 Content-Type 不带 `codecs`，不是不支持。
  - **Range 定位**：限速下拖动到 60%，Chrome 发起新的 `Range: bytes=N-` 请求，Go 服务返回 206，0.1–0.3 秒完成跳转，随后继续出声。
  - **MP3 起播延迟**：Chrome 在 `loadedmetadata` 之前要读约 2.4 MB 的 MP3 数据，与标签大小、`preload` 无关（2 Mbit/s 下约 10 秒，8 Mbit/s 下 2.45 秒，按带宽线性缩放）。OGG 只要 0.2–0.6 秒。换算起播延迟：局域网（100 Mbit/s）约 0.2 秒，20 Mbit/s 约 1 秒。
  - **损坏文件**：中间清零的 MP3 能越过损坏处继续播放，没有错误事件，也没有停顿。元数据不完整的 FLAC 在上传时即被拒绝（422 `corrupt_file`）。
  - **自动播放与 `AudioContext`**：页面未被点击时，`AudioContext` 为 `suspended`，`play()` 抛 `NotAllowedError`；点击后 `resume()` 成功，`play()` 可用。默认策略与 `document-user-activation-required` 结果相同。由于恢复播放时不自动播放（见“播放行为”），播放端只需在第一次用户操作时创建或恢复 `AudioContext`。
  - **`setSinkId`**：`HTMLMediaElement` 与 `AudioContext` 都支持；`setSinkId("")` 和 `{type: "none"}` 成功，未知设备抛 `NotFoundError`。无头环境没有输出设备，设备列表与真实切换未验证。
  - **均衡器链路**：10 段滤波串联后正常出声，跳转后信号正常。
- [x] 结论：**阶段 4 不做服务端转码**。五种格式在 Chromium 中都能直接流式播放与跳转；MP3 的起播延迟 Eric 确认可以接受（2026-10-25）。
