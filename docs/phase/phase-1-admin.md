# 阶段 1：Go 服务基础与管理后台

状态：下一步执行。参照路线图：[运行环境与后端范围](../roadmap.md#42-运行环境与后端范围)。

管理后台是另行开发的 Web 界面，负责上传音乐和维护曲库，使播放端只呈现流媒体体验。SPlayer 没有对应界面，**管理后台不受 SPlayer 样式复刻约束**。

## 已确定（2026-10-23）

- 视觉：Naive UI 默认风格，不做主题定制。
- 工程：独立前端工程 `admin/`，与 `frontend/` 组成 pnpm workspace；技术栈与播放端一致（Vue 3、TypeScript、Naive UI、Vite），依赖版本由同一份锁文件管理。生产环境由 Go 服务托管两份静态产物，管理后台挂在 `/admin/`，同一容器、同一端口。
- 音乐只能通过管理后台上传入库；挂载目录是服务独占的存储卷，不支持手动放入文件。
- 管理员：首次使用服务时，在管理后台页面上输入容器日志中的初始化 token、用户名和密码创建管理员；之后不再显示初始化页面。管理后台不走 OIDC。
- 开发环境写死一个管理员和一个普通用户，跳过初始化页面、初始化 token 与 OIDC。
- 下列工作包作为首发范围的起点，开发中按实际情况灵活调整。

## 工作包

### 1.1 Go 服务骨架

- [ ] 初始化 `backend/` Go 模块，接入 Taskfile 的 lint、test、run；本地开发直接运行 Go 程序，不在本机构建容器镜像。
- [ ] 沿用 `../homepage` 的基础选择，以便阶段 4 原样照搬其 OIDC 代码：标准库 `net/http` 路由、modernc SQLite、YAML 配置文件加环境变量覆盖密钥。
- [ ] 配置：媒体存储卷与数据卷（SQLite、封面缓存）的路径；开发模式开关。
- [ ] 开发模式：写死的管理员与普通用户只在开发模式生效，生产配置无法启用。

### 1.2 管理员初始化与登录

- [ ] 服务启动时若不存在管理员，生成一次性初始化 token（加密安全随机数），写入标准输出，即容器日志，并附带初始化页面地址。token 只保存在内存中；服务重启后重新生成，旧 token 失效。
- [ ] 服务中不存在管理员时，管理 API 只开放初始化接口；管理后台检测到未初始化时显示初始化页面，输入初始化 token、用户名、密码与确认密码。
- [ ] 初始化接口以常量时间比较 token；token 错误时拒绝并限制尝试频率；初始化成功后 token 立即作废。
- [ ] 初始化接口只能成功一次，并发请求只有一个生效；初始化完成后接口返回错误。
- [ ] 密码以慢哈希保存（如 bcrypt 或 argon2id），不写入日志。初始化 token 是唯一写入日志的凭据，仅在未初始化时输出。
- [ ] 登录、退出、会话过期；管理会话 Cookie 限定在管理路径，与播放端会话互不通用。
- [ ] 部署说明写明：通过 `docker logs`（或对应容器平台的日志）获取初始化 token。

### 1.3 曲库模型与上传入库

- [ ] 曲库模型：歌曲、专辑、艺术家；媒体有稳定 ID，文件路径只在服务内部使用，不出现在 API 中。存储卷内的文件布局由服务决定。
- [ ] 上传：多文件上传，读取标签（标题、艺术家、专辑、专辑艺术家、音轨号、时长、年份）、内嵌封面、内嵌与同名外置歌词，写入存储卷；处理重复文件、缺标签与损坏文件。
- [ ] 删除歌曲：同时清理存储卷文件；播放端上线后还需处理歌单、喜爱、历史中的引用。
- [ ] 用真实音频样本测试上传、去重与失败路径。

### 1.4 管理 API

- [ ] 初始化、登录、退出、会话状态。
- [ ] 上传与入库结果、歌曲/专辑/艺术家的列表、详情与修改、合并、删除、封面与歌词的上传替换删除、曲库概况。
- [ ] 统一错误格式与 API 版本约定（播放端 API 后续沿用）。

### 1.5 管理后台界面

- [ ] 初始化 `admin/` 与 pnpm workspace，接入 Taskfile 的 lint、build、run；开发服务器代理管理 API 到 Go 服务。
- [ ] 初始化页面、登录页、退出。
- [ ] 上传：多文件上传，显示每个文件的进度、入库结果与失败原因；重复文件提示。
- [ ] 元数据：编辑歌曲、专辑、艺术家；合并重复的艺术家与专辑；筛选缺标签的歌曲。
- [ ] 封面与歌词：上传、替换、删除。
- [ ] 曲库概况：歌曲、专辑、艺术家数量与存储占用。

## 退出条件

- 全新数据卷启动后，用容器日志中的 token 能在页面上完成管理员初始化；缺少或错误的 token、重启前的旧 token 和重复初始化均被拒绝。
- 管理员能完成上传入库与元数据维护，重启服务后数据保持。
- 上传失败、文件损坏、会话过期和服务不可达有明确状态。
- 开发模式下无需初始化与 token，即可用写死的管理员登录。
