关键发现（不要回退）：
- 接口服务响应缓存 2 分钟，缓存键不含 POST 正文；netease 客户端每个请求都带 x-apicache-bypass 且 URL 唯一。新增调用一律走 backend/internal/netease 的 call。Go 只开放具名接口，不做通用转发。
- 退出网易云只删 Sonora 的会话，不调上游 /logout。编辑在线歌单用 /playlist/name/update 和 /playlist/desc/update。在线歌单写操作先确认是自己创建的（ownNeteasePlaylist）。
- /album/sub、/artist/sub、/playlist/subscribe：t == 1 是收藏，其他值是取消（Sonora 发 1/0）。
- /album、/artists、/recommend/songs 的歌曲自带 privilege.st，/song/detail 的分开；st < 0 不可播放。/album 的歌没有 publishTime，年份取专辑；碟号可能是 "01"、"02 [Target Deluxe Edition]"，只取开头的数字。
- 专辑唯一键 title（NOCASE，仅 ASCII）+ artist_key；导入专辑带 #netease:<歌曲ID> 或 #netease:album:<专辑ID> 后缀，rekey、UpdateAlbum、编辑歌曲都要保留。单曲导入建的专辑标为“单曲”，首页“最近添加的专辑”不显示单曲专辑。
- 只有配置了 import_group 才请求 groups scope（否则 Authelia invalid_scope 让所有人登录不了）。
- 播放端源码不能出现 music.163.com、MUSIC_U，模块路径不能含 netease、cookie（frontend/boundaries.mjs）。播放端字段用 online 的叫法（source: "online"、onlineId）。lint 报错时改命名或移到 Go，不要放宽规则。管理后台不受这条约束。
- 本地与网易云 ID 可能相同：比较歌曲用 frontend/src/utils/track.ts 的 sameTrack、trackKey；列表用 listKey、listRoute；在线详情页用 onlinePageRoute；艺术家与专辑链接用 artistRoute、albumRoute。
- 首页卡片和问候语不要按登录状态切换显示内容：账号是载入后才读到的，会闪。问候语等 userStore.neteaseChecked 后才显示名字。
- 播放地址带时效，不能存入队列。不可播放的歌在队列入口过滤。n-image 要传 object-fit 属性。新的列表页要加进 style/main.scss 的“列表页通用样式”。
