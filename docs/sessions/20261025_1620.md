下一步：4.4 Playback（按 docs/phase/phase-4-playback.md 的清单）
1. 先读 SPlayer 的 core/player/（PlayerController.ts、SongManager.ts、PlayModeManager 等）和 core/audio-player/，确定接入方式：
   - 只用 Web Audio / HTMLAudioElement，不迁入 MPV、自动混音、网易取地址。
   - 音频地址用 DataSource.audioUrl(trackId)。
   - 方法名和流程沿用 SPlayer，让已照搬的组件不用改。
2. Playback 是播放状态的唯一所有者。状态机为 idle → resolving → loading → playing / paused → ended，失败进入 error。
   - 切歌带请求标识并可取消：先点 A 后点 B，A 较晚返回也不能覆盖 B。
   - 解析中暂停不得自动播放。
3. 队列与播放模式：
   - 队列条目要有独立身份，允许重复入队。这与 SPlayer 的 setNextPlaySong 按歌曲 ID 去重不同，动手前先列出差异问 Eric。
   - 播放模式：顺序、列表循环、单曲循环、随机（随机时打乱队列，保留 originalPlayList）。
4. 播放超过 min(30 秒, 时长的一半) 才写最近播放（POST history）。
5. 播放失败自动跳过，最多连续 3 首，然后停止并提示。补采阶段 2 缺的“底部栏播放错误”状态时可以对照。
6. 喜欢接上 PUT/DELETE likes，替换 utils/auth.ts 里的 toLikeSong 提示；写入未确认时不显示为已保存。
7. 队列和播放位置保存在浏览器中，重启后恢复为可继续播放的状态，不自动播放。另外还有阻止息屏、MediaSession、频谱与低频音量（全屏播放器的频谱和背景响应在等它）。
8. 单元测试覆盖切歌竞态、解析中暂停、队列编辑与恢复。
   - 前端目前没有测试框架。引入 vitest 等新依赖前先确认，并同步 visual-assets/THIRD_PARTY_NOTICES（如适用）。
   - 接入后 fixture 场景（?fixture=baseline&player=...）仍要可用，task test:visual 不能回归。
9. 退出条件中的整条链路要在 Chrome 里真实可听：上传 → OIDC 登录 → 入队 → 播放/暂停/拖动/切歌 → 歌词 → 重启恢复。需要 Eric 手动听的部分请他确认。

经验：
- 截图差异要找原因时：
  - 先在两边量元素的精确坐标（getBoundingClientRect）。
  - 再用 CDP 的 LayerTree 对比合成层。
  - 最后在 SPlayer 上换步骤截图，或删掉某个元素再截，排除采集步骤和原项目额外元素的影响。
  - 前景整体差 1–2 时，先看是不是封面取色的随机性。
- 加载 fixture 状态的路径上不要多加 await，曾让底部栏截图随机出差异。
- 访问 pinia：
  - 生产构建的 SPlayer 里，pinia 从 document.querySelector("#app").__vue_app__.config.globalProperties.$pinia 取，播放控制器在 window.__SPLAYER_PLAYER_CONTROLLER__。
  - Sonora 开发版取 pinia 的方式相同，store 名称也相同（data、music、status、setting）。
- 用临时脚本访问参考实例：
  - 要在 setting-store 预置 schemaVersion: 12 和 userAgreementVersion: "v2.0"，否则会弹协议对话框。
  - --sonora 采集还要清空 playSong.alia。
- 设置的存储位置：Sonora 在 localStorage 的 sonora-setting（status 在 sonora-status，搜索历史在 sonora-data），SPlayer 在 setting-store。两边设置的字段名和默认值相同。
- Playwright 选择器：SongList 的表头也带 .song-card 类，选歌曲行要用 ".virtual-item .song-card"。
- 起临时 Vite：直接用 node frontend/node_modules/vite/bin/vite.js，PID 就是实际监听进程。如果用 pnpm exec vite，记录的是 pnpm 外壳的 PID，要用 ss -ltnp 找到真正监听端口的进程再结束。
- 让 Vite 代理到临时后端：vite.config.ts 的代理写死 14560。可以在 /tmp 写一个配置，导入 frontend/vite.config.ts，覆盖 server.proxy 和端口，再用 --config 启动。
- 格式化：文档在 HEAD 里本来就没有用 Prettier 格式化，不要整篇重排。scripts/ 下的 .mjs 用 frontend/node_modules/.bin/prettier 格式化。
- 前端 ESLint 与 SPlayer 相同，_ 开头的变量和参数视为有意不用。照搬代码报 any 或三元表达式语句时，按已有先例逐行加 eslint-disable-next-line。
