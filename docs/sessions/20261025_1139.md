经验：
- 生产构建的 SPlayer 里 app._instance 为空，读组件树要从 document.querySelector("#app")._vnode 开始。pinia 从 document.querySelector("#app").__vue_app__.config.globalProperties.$pinia 取，播放控制器在 window.__SPLAYER_PLAYER_CONTROLLER__。Sonora 开发版用同样方式取 pinia，store 名称与 SPlayer 相同（status、music、data、setting）。
- Sonora 的设置保存在 localStorage 的 sonora-setting 键，SPlayer 的在 setting-store。
- 参考实例页面里出现的 “Request failed with status code 405” 是网易接口的报错，与界面无关。
- 截图差异要找原因时，先在两边量元素的精确坐标（getBoundingClientRect 或 Range），再在 SPlayer 上换一种操作步骤截图，排除采集步骤本身造成的差异。
- AMLL 1.0.1 的 parseTTML 会跳过没有 itunes:key 的 <p>；它需要 DOMParser，所以 Node 里跑不了，要在 Chromium 里执行。
- Naive UI 的 menu.showOption 要等菜单渲染出对应项之后再调用，相关 watch 要用 flush: "post"。
- 文档在 HEAD 里本来就没有用 Prettier 格式化，不要整篇重排。scripts/ 下的 .mjs 用 frontend/node_modules/.bin/prettier 格式化。
- 前端 ESLint 和 SPlayer 一样，以 _ 开头的变量和参数视为有意不用。
