4.4 的实现（细节见 phase-4-playback.md）：
- 控制器：frontend/src/core/player/PlayerController.ts 就是 Playback，是播放状态、队列与播放模式的唯一所有者。
  - 方法名沿用 SPlayer；store 的 playStatus、playLoading 只由它的 setState/sync 写入。
  - 状态：idle / resolving / loading / playing / paused / ended / error。
  - 防竞态：请求标识 currentRequestToken 和尝试序号 playAttempt 丢弃过期结果；用户的播放意图 wantPlay 与状态分开记录。
  - 依赖从构造函数注入（PlaybackDeps）。浏览器里的默认依赖在 core/player/browserDeps.ts；fixture 模式用不出声的 SilentAudioPlayer 和内存存储。
- 音频：core/audio-player/ 照搬 SPlayer 的 Web Audio 引擎，去掉 MPV、FFmpeg、自动混音、倍速、ReplayGain。
- 队列：core/player/queue.ts。条目是 Track 加 entryId，允许重复入队，比较一律用 entryId。
- 保存与恢复：core/player/storage.ts 存到 IndexedDB 的 sonora/player，queue 与 position 分开存；重启后恢复为暂停，且不加载音频。
- 其他新文件：MediaSessionManager.ts（Web API）、wakeLock.ts（Screen Wake Lock）。
- Eric 确认的、与 SPlayer 不同的行为：
  - 允许重复入队；
  - 开启随机时当前曲目放第一位，随机期间的增删同时作用于 originalPlayList；
  - 不循环时播完最后一首停在末尾；手动“下一首”仍绕回第一首；
  - 播放失败不重试，连续 3 首失败、只有一首或已是最后一首时，停止并提示，不清空队列；
  - 播放超过 min(30 秒, 时长的一半) 才 POST history，按实际收听时长累计，跳转不计入。
- 喜欢：utils/auth.ts 的 toLikeSong 接上了 PUT/DELETE likes，服务端确认后才更新。
- DataSource 新增 like、unlike、recordPlay、audioStatus。audioStatus 用 Range 请求区分 401、404 和服务不可达。
- 测试：vitest 5.0.5，frontend/vitest.config.ts，29 个测试在 PlayerController.test.ts。运行 task test:frontend，已接入 task test。

经验：
- 截图对照：
  - task test:visual 的 set-yrc-amll（偶尔也有 full-yrc-amll）会随机截到不同的歌词帧，常见数字是 17946 px、最大差值 47。HEAD 上同样出现，单独重跑能对上，原因未查明。
  - 判断是否回归：用 git stash -u 在 HEAD 上用同样的 --only 跑几次，比较出现频率。
  - 截图差异要找原因时：先用 getBoundingClientRect 量两边元素的精确坐标；再用 CDP 的 LayerTree 对比合成层；最后在 SPlayer 上换步骤截图，或删掉某个元素再截。前景整体差 1–2 时，先看是不是封面取色的随机性。
  - 加载 fixture 状态的路径（initPlayer → loadState）上不要多加 await，曾让底部栏截图随机出差异。
- 无头真实播放：
  - 开发服务器上可以在页面里 await import("/src/core/player/PlayerController.ts")，再 usePlayerController()，拿到与页面相同的实例。
  - pinia 从 document.querySelector("#app").__vue_app__.config.globalProperties.$pinia 取，store 名称为 data、music、status、setting。
  - 用真实点击触发播放，否则会受自动播放限制。
  - 底部栏按钮：.main-player .play-pause、.main-player .like；上一首、下一首是 .play-control .play-icon 的第 2、3 个。
- 临时实例：
  - Vite 配置写在 /tmp 时，从 frontend/node_modules/vite/dist/node/index.js 绝对路径导入 mergeConfig；直接 import "vite" 会找不到包。
  - 后端数据库用 sqlite3 .backup 复制（开发服务器可能在写 WAL），covers 直接复制，媒体目录只读软链接。
- vitest：
  - @material/material-color-utilities 与 @imsyy/color-utils 要在 server.deps.inline 里交给 Vite 转换。
  - store 定义时引用 localStorage，vitest.setup.ts 给了内存实现。
  - 测试里要 vi.mock("@/api/source")。
- 设置的存储位置：
  - Sonora：localStorage 的 sonora-setting（status 在 sonora-status，搜索历史在 sonora-data），播放队列在 IndexedDB 的 sonora。
  - SPlayer：setting-store。两边设置的字段名和默认值相同。
- 用临时脚本访问参考实例：要在 setting-store 预置 schemaVersion: 12 和 userAgreementVersion: "v2.0"，否则会弹协议对话框；--sonora 采集还要清空 playSong.alia。
- Playwright 选择器：SongList 的表头也带 .song-card 类，选歌曲行要用 ".virtual-item .song-card"。
- 起临时 Vite：直接用 node frontend/node_modules/vite/bin/vite.js，PID 就是实际监听进程，可用 ss -ltnp 核对。
- 格式化：
  - 文档在 HEAD 里本来就没有用 Prettier 格式化，不要整篇重排。
  - frontend 与 scripts/ 下的 .mjs 用 frontend/node_modules/.bin/prettier 格式化。
- 前端 ESLint 与 SPlayer 相同：_ 开头的变量和参数视为有意不用。照搬代码报 any 或三元表达式语句时，按已有先例逐行加 eslint-disable-next-line。
