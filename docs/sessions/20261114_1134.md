# 交接：安卓端音量均衡（响度标准化）

仓库 Sonora，main 分支。先拉到包含以下两个提交的版本：
- `4e9cf69 feat(backend): measure loudness and hand players a normalization gain`
- `68c8cda feat(player): apply the server's loudness gain with a volume normalization switch`

开始前按全局约定读 memories/AGENTS.md 和 AGENTS.md。用中文和 Eric 交流，提交前先问他；提交信息沿用仓库风格：英文 conventional 标题，中文正文，正文末尾写验证情况。

## 已完成的部分（Linux 开发机）

- 服务端测量每首歌的积分响度和真峰值（BS.1770 / EBU R128），在后台补算，新歌入库后立即测量。
- 播放端 API 的歌曲新增 `gainDb`（单位 dB，保留两位小数，可以为 `null`）。这是服务端算好的最终增益：
  - 每首歌按自己的响度调到 -16 LUFS，**不区分专辑与单曲**。
  - 调小不受限；调大时真峰值不超过 -1 dBTP。
  - 没测或测不了（M4A、Opus、解码失败）时为 `null`，表示按原音量播放。
- 测量结果写入后会进入曲库变更日志，所以 `GET library/changes` 返回的歌曲同样带着 `gainDb`，安卓同步就能拿到。
- 详细说明见 `docs/api.md` 的“音量均衡”一节。
- Web 端：设置里有“音量平衡”开关，默认开启；在线歌曲不做均衡。

## 已定的决策（不要再讨论）

1. **用 `player.volume` 施加增益，不用 AudioProcessor。** 原因有两个：
   - DualPlayerEngine 默认开启 audio offload，开启后 AudioProcessor 不运行。
   - 处理器位于缓冲之后，换歌时增益切换会偏离歌曲边界几百毫秒。
   
   引擎里保留了 PixelPlayer 的 ReplayGain 钩子（`DualPlayerEngine.incomingTrackReplayGainVolume`、`volumeBeforeTransition`），交叉淡入淡出已经会读它。
2. **增益大于 0 dB 时截到 1.0**（volume 不能超过 1）。开发库 369 首里只有 10 首需要调大，最多 +4.5 dB，可以接受；调小的 350 首不受影响。
3. **在线歌曲不做均衡。** 安卓目前没有在线播放，但取增益的地方要留出这个判断，以后加在线歌曲时只会是 `null` 或被跳过。
4. **设置开关默认开启。** Web 上叫“音量平衡”，与 SPlayer 一致；安卓沿用这个叫法，除非原版 PixelPlayer 已有对应设置项可照搬。
