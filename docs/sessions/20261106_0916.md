关键发现（不要回退）：
- 接口服务的响应缓存 2 分钟，缓存键不含 POST 正文。netease 客户端每个请求都带 x-apicache-bypass 且 URL 唯一，否则用户之间会串数据。新增调用一律走 backend/internal/netease 的 call。
- Go 只开放具名接口，不做通用转发，上游响应会回传 Cookie。
- 退出网易云只删 Sonora 的会话，不调上游 /logout，否则同一 Cookie 在其他客户端也会失效。
- 编辑在线歌单不用 /playlist/update：它不传标签时会清空标签，还把值不转义地拼进 JSON。改用 /playlist/name/update 和 /playlist/desc/update，只发改动的字段。
- 在线歌单写操作先确认是该账号自己创建的（ownNeteasePlaylist），“我喜欢”和收藏的歌单在网易云上也是歌单。
- /playlist/tracks 成功时响应包在 body 里，拒绝时不包。
- /album 和 /artists 的歌曲自带 privilege.st，/song/detail 的 privileges 是分开的；st < 0 表示不可播放。
- 只有配置了 import_group 才请求 groups scope：Authelia 对未获准的 scope 返回 invalid_scope，无条件请求会让所有人登录不了（契约测试 TestAutheliaGroups 已证实）。组成员关系在登录时存入 users.idp_groups，变动要重新登录才生效。
- albums 对标题加 artist_key 有唯一索引。导入的专辑在 artist_key 带 #netease:<歌曲 ID> 后缀来并存（importedKey、rekey），UpdateAlbum 和 rekeyAlbums 都保留后缀。上传不会并入它们，管理后台可以合并。
- 导入的歌曲同时保留单曲封面和专辑封面，这样合并专辑后歌曲还有自己的封面。
- yrc 转 TTML 在 backend/internal/netease/lyrics.go：翻译优先 ytlrc 后 tlyric，罗马音同理，按开始时间对齐，容差 300 毫秒；单词之间的空格放在 span 之间；网易云的 “//” 不放入。在线播放走同一个转换。
- 本地与网易云的歌曲、专辑、歌单 ID 都是整数，可能相同。比较歌曲用 frontend/src/utils/track.ts 的 sameTrack、trackKey；列表用 listKey、listRoute；艺术家和专辑链接用 artistRoute、albumRoute。statusStore.getSongOffset 仍按数字 ID 取，是已知的小缺口。
- 不可播放的歌曲在队列入口过滤（updatePlayList、addNextSong、addNextSongs）。
- 播放地址带时效，不能存入队列，刷新恢复后点播放时才重新取。
- 自动关闭没有照搬 SPlayer 的三个缺陷：关闭后下一秒暂停、第一次打开不计时、超过 60 分钟时显示回绕。
- 截图对照：播放器后面的首页先画出的字会改变翻译行的字体回退。scripts/visual/player.mjs 为此固定上午时间，并隐藏“最近添加的歌曲”栏目（首页不参与对照）。遇到 full-yrc 435 px、set-yrc 726 px 这种数字，先查这个原因。
- frontend/boundaries.mjs 的边界不变：播放端源码不能出现 music.163.com、MUSIC_U 等字面量，导入路径不能含 netease、cookie。遇到 lint 报错时改命名或改到 Go，不要放宽规则。
- ENABLE_GENERAL_UNBLOCK 不设置（Eric 决定）。不做灰色歌曲解锁。
