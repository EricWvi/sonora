关键发现（不要回退）：
- 接口服务的响应缓存 2 分钟，缓存键不含 POST 正文。netease 客户端每个请求都带 x-apicache-bypass 且 URL 唯一，否则用户之间会串数据。新增调用一律走 backend/internal/netease 的 call。
- Go 只开放具名接口，不做通用转发，上游响应会回传 Cookie。
- 退出网易云只删 Sonora 的会话，不调上游 /logout，否则同一 Cookie 在其他客户端也会失效（参考实例就共用这个 MUSIC_U）。
- 本地与网易云的歌曲 ID 都是整数，可能相同，比较歌曲一律用 frontend/src/utils/track.ts 的 sameTrack、trackKey。statusStore.getSongOffset 仍按数字 ID 取，是已知的小缺口。
- 播放地址带时效，不能存入队列。
- frontend/boundaries.mjs 的边界不变：播放端源码不能出现 music.163.com、MUSIC_U 等字面量，导入路径不能含 netease、cookie。这是 Cookie 登录组件叫 LoginPaste.vue、二维码地址由 Go 返回的原因。遇到 lint 报错时改命名或改到 Go，不要放宽规则。
- ENABLE_GENERAL_UNBLOCK 不设置（Eric 决定）：代码只在等于 true 时开启，镜像没有设置，所以就是关闭。不做灰色歌曲解锁。
- 接口包的镜像是 moefurina/ncm-api:4.41.1，版本写在 Taskfile.yml 和 docs/deployment.md 两处，要保持一致。
- 开发机不保留接口包的源码，用镜像运行。
