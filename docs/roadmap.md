# Sonora 重写路线图

更新日期：2026-10-22。状态：调研后的实施建议，尚未开始实现。

## 1. 目标与已确定的约束

Sonora 重新实现播放器的业务和数据架构，界面样式完全按照 `reference/SPlayer` 还原。重写的原因是原项目与网易云音乐耦合过深，后续修改成本高。这个方向已由 Eric 确定，见[项目说明](../README.md)。

**严格复刻 SPlayer 样式是已确定的硬性约束，不属于下文可选的实施建议。** 所有实现页面的布局、配色、字体、字号、间距、尺寸、图标、圆角、阴影、透明度、动效和交互状态，都必须以 `reference/SPlayer` 的源码与实际渲染为准逐项还原。分阶段接通功能和接入自研音乐服务，都不能成为改变页面结构、简化样式或省略视觉状态的理由。

未经 Eric 明确同意，不得重新设计或替换原有视觉方案。每个页面和每个阶段都必须满足第 6 节的视觉验收要求，不能以功能已完成代替样式验收。

音乐服务方向已确定：Sonora 舍弃网易云音乐来源，使用我们自己开发的音乐服务，不实现网易登录、Cookie 导入、网易接口适配或网易播放地址解析。原项目的网易相关源码只用于识别需要移除的耦合；原账号仅用于查看参考界面的不同状态。

本路线图中的技术选型、首发范围和阶段顺序是建议，不代表 Eric 已确认所有取舍。自研音乐服务的现有实现、接口协议和开发位置尚未调研，下面定义客户端所需契约与联调任务，不假定接口已经存在，也不擅自确定服务端技术栈。

## 2. 调研依据与证据边界

- 源码基线：SPlayer `3.1.1`，子模块提交 `28b76bad9eb800e0c90dac8475d4769acfe2450b`；后续更新子模块时应重新评估差异。版本来自 [package.json](../reference/SPlayer/package.json)。
- 本地参照：`http://localhost:25884`。本次已通过真实 Chromium 确认首页能打开；未带 Cookie 时显示“未登录”，注入用户提供的 Cookie 后登录状态接口返回有效资料，右上角显示账号名。首启协议弹窗存在。
- 本次没有逐页完成真实交互验收，没有实测桌面打包、各音频引擎、音频输出设备或所有私有流媒体协议；下文有关这些能力的描述是源码发现，不是运行通过的结论。
- 源码调研详见 [SPlayer 调研记录](splayer-research.md)。外部技术依据限于 Vue、Electron、Tauri 和 Playwright 的官方资料，链接附在相关段落。
- 当前 Sonora 主要只有说明文件和参考子模块，尚无自身应用工程。下文路径是拟议结构，不能当成现有实现。

## 3. 重写要解决的具体问题

| 原项目现状与证据 | 对修改的影响 | Sonora 的目标 |
| --- | --- | --- |
| 请求默认走网易接口，并在请求参数中拼接 `MUSIC_U`，见 [request.ts](../reference/SPlayer/src/utils/request.ts) | 页面、鉴权与单一平台请求方式绑定 | 平台请求与会话只在对应 Adapter 内处理 |
| 用户区域主动检查网易登录并刷新用户资料，见 [User.vue](../reference/SPlayer/src/components/Layout/User.vue) | 无账号、账号过期与播放器初始化容易相互影响 | 登录状态属于具体来源，播放器可以独立启动 |
| 路由以 `needLogin` / `needApp` 判断访问权限，见 [router/index.ts](../reference/SPlayer/src/router/index.ts) | 平台身份与本地能力混为全局条件 | 依据页面真正需要的来源会话或运行环境能力判断 |
| `SongType` 混合数字 ID、会员标记、云盘、本地路径和流媒体服务器字段，见 [types/main.ts](../reference/SPlayer/src/types/main.ts) | 新来源要迎合既有字段，同 ID 也可能产生歧义 | 自有媒体身份与来源引用分离，平台字段不进入通用模型 |
| 播放控制器直接读写多个 Pinia Store，歌曲管理器分支处理来源，见 [PlayerController.ts](../reference/SPlayer/src/core/player/PlayerController.ts)、[SongManager.ts](../reference/SPlayer/src/core/player/SongManager.ts) | 播放状态、取地址、UI 与持久化难以单独验证 | 播放会话只有一个状态所有者，来源解析可替换 |
| 主题由 Naive UI 覆盖、动态配色、全局 SCSS 和组件内样式共同决定，见 [Provider.vue](../reference/SPlayer/src/components/Global/Provider.vue)、[main.scss](../reference/SPlayer/src/style/main.scss) | 单独复制 CSS 无法得到完整原样式 | 固定视觉基线，并整体理解主题生成链路 |

不采用“复制整个项目后逐步删网易代码”的主路径。可以逐项复用已确认的视觉资源与局部实现，但每项都要交代来源、依赖和验证方式，避免旧 Store、请求逻辑和平台字段被一并带入。

## 4. 技术方向与需要先验证的选择

### 4.1 前端建议

建议沿用 Vue 3、TypeScript、Naive UI、SCSS 的组合，以降低原样式复刻时的结构和组件差异；重新组织业务逻辑，不直接移植原页面的全部脚本。原项目的依赖版本只作为复现基线，Sonora 的版本应在工程初始化时锁定，并验证构建兼容性。Vue 官方说明 SFC 将模板、逻辑、样式放在同一文件，因此复用视觉部分时要显式检查脚本依赖，不能把复制 `.vue` 文件当成纯样式迁移。参见 [Vue SFC](https://vuejs.org/guide/scaling-up/sfc) 和 [TypeScript 支持](https://vuejs.org/guide/typescript/overview)。

浏览器预览用于快速验证页面、业务和视觉；桌面能力通过单独的 Platform Interface 接入。浏览器版本的完成不能作为文件扫描、托盘、桌面歌词等桌面功能完成的证据。

### 4.2 桌面壳的候选比较

| 方案 | 对本项目的收益 | 需要验证的代价 | 建议 |
| --- | --- | --- | --- |
| Electron | 与原项目更接近，便于对照 Chromium 渲染和桌面功能 | 包体、资源占用、原生依赖打包与进程隔离 | 默认优先验证的方案，并非已定案 |
| Tauri + Rust | 可把本地业务放入 Rust Core，使用系统 WebView | 不同系统渲染与媒体能力差异，原有 Electron 能力需重接 | 若 Rust 核心或包体目标更重要，再用同页原型比较 |
| 仅 Web | UI 调试与交付路径简单 | 无法直接覆盖原项目全部桌面能力 | 可作为预览环境，不先假定是最终唯一产品 |

Tauri 官方说明其使用系统 WebView，而非随应用捆绑同一套引擎，因此像素还原与音频能力必须按目标系统验证；这不是已测得的性能结论。见 [Tauri 进程模型](https://tauri.app/concept/process-model/)。

若使用 Electron，不照搬原项目关闭 `sandbox` / `webSecurity` 并打开 Node 集成的窗口默认配置，见 [windows/index.ts](../reference/SPlayer/electron/main/windows/index.ts)。按官方建议使用隔离、受限 IPC、受控导航与权限；若音频方案依赖更宽权限，先做最小实验并记录原因。见 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security/)。

## 5. 拟议模块与数据契约

模块应把复杂行为藏在小而稳定的 Interface 后面。Seam 放在实际会变化的位置：音频引擎、媒体来源、存储、运行环境。不先建插件市场、运行时插件系统或覆盖所有平台的巨大接口。

| Module | 对外承担的行为 | 内部处理的复杂性 |
| --- | --- | --- |
| Playback | 播放队列、播放/暂停、跳转、上一首/下一首和状态订阅 | 解析、加载、过期请求取消、错误分类、曲目切换与资源释放 |
| Library | 本地收藏、歌单、历史与媒体索引 | 持久化、事务、排序与数据迁移 |
| Catalog | 浏览、搜索、获取实体详情 | 分页、缓存和来源 DTO 转换；只暴露当前已实现能力 |
| Service Session | 自研音乐服务的登录、失效和退出 | 服务端确认的认证方式、凭据和会话更新 |
| Lyrics | 获取与解析歌词、按时间输出可渲染内容 | LRC/逐字格式、翻译、音译与偏移 |
| Platform | 文件选择、扫描、系统媒体控制和窗口功能 | Electron/Tauri/浏览器的具体差异 |
| Presentation | 按 SPlayer 样式展示 ViewModel 并发出用户意图 | 主题和视觉状态，不直接知道网易 Cookie 或响应结构 |

Catalog 先围绕自研音乐服务的实际契约设计，不为了兼容网易或假想的多个平台建立统一大接口。推荐、评论、播客等能力是否提供，由自研服务和首发范围决定；暂不支持的功能通过明确的能力结果表达，页面保留原视觉语言并呈现适当状态。本地文件能力是否首发另行确定。

### 5.1 媒体身份与能力

- 媒体在 Sonora 内有稳定身份；外部引用至少包含来源类型、实例/服务器、实体类型和原始字符串 ID。不要把所有外部 ID 强制转换成数字。
- 同名歌曲不自动视为同一首；多来源匹配另行设计，不能在播放失败后静默替换成别的录音。
- 队列中的一次出现有独立条目身份，允许同一首歌重复入队；删除、拖动和恢复按条目处理。
- `Track` 存元数据，`PlayableResource` 表达这次解析的临时播放资源、有效期和所需传输方式。过期地址不作为永久数据源保存。
- 收藏、喜爱、歌单编辑区分本地操作与自研服务端写入；不能把本地点赞显示成服务端已成功同步。
- 来源能力与当前权限分别判断。支持高音质不代表当前账号有权播放；失败返回明确原因，不映射成通用“网络错误”。

### 5.2 播放状态与异步规则

拟议状态：`idle → resolving → loading → playing / paused → ended`，失败进入 `error`；拖动、切歌和重试的事件由同一个 Playback Module 接收。

- 每次切歌分配请求标识并取消旧解析。用户先点 A 后点 B，即使 A 更晚返回，也不能覆盖 B。
- 暂停发生在解析中时，解析完成不得擅自自动播放；用户手势触发与浏览器自动播放限制要单独处理。
- 取地址失败、无权限、编码不支持、设备异常、用户取消分别表达；自动跳过要有上限，不能陷入无限循环。
- 歌词、封面、系统媒体信息和进度都跟随当前播放条目；旧事件不能修改新条目。
- 保存队列和播放位置，默认恢复为可继续播放的状态，不把启动后自动播放当成隐含承诺。

### 5.3 存储与凭据

建议桌面结构化数据使用 SQLite，媒体文件与缓存单独管理；浏览器预览使用自己的轻量存储 Adapter。选型在阶段 2 验证迁移、事务与重启恢复后确定。

凭据只进入对应会话存储。用户提供的 `only_session` 只用于本地验证，不写入文档、fixture、截图元数据、日志或 Git。前端不自行拼接平台 Cookie；远端请求参数和日志需要脱敏。这里规定的是 Sonora 的目标，不能把本次原项目 Cookie 验证方式当成生产实现。

## 6. 样式还原与验收方法

本节是所有页面交付的强制标准。每个页面须列出对应的 SPlayer 页面、状态和参考图，在相同环境、视口、主题、数据和交互状态下完成截图对照与交互检查，留下参考图、实际图、差异图和结论。布局、字号、间距、图标、颜色及动效的已知偏差未修正前，不能标记该页面或对应阶段完成。

范围同时覆盖主页面、导航、播放器、设置、菜单、弹窗、抽屉，以及加载、空态、错误、悬停、焦点、选中、展开和响应式状态。首发范围决定哪些功能先交付，不能降低已交付页面的复刻精度。

无法消除的系统渲染差异须记录原因、复现条件和对比证据，由 Eric 明确确认例外；不得自行改设计、放宽全局阈值或替换基线使其通过。自研服务产生的新状态优先沿用原项目对应组件及视觉规范，涉及新增视觉方案时需明确确认。

### 6.1 基线采集

阶段 0 建立独立的“原项目参考图”和“Sonora 实际图”，不能用 Sonora 首次截图直接替代 SPlayer 基线。记录源码提交、系统、浏览器版本、字体、视口、DPR、主题、缩放、数据和交互步骤。

采集要覆盖：

| 页面/区域 | 最低状态集合 |
| --- | --- |
| 主框架 | 侧栏展开/折叠、桌面/窄屏、顶部搜索、用户入口、底部播放器 |
| 首页/发现 | 已登录/未登录、卡片网格、骨架、空态、失败和重试 |
| 搜索 | 默认建议、输入建议、多类结果、无结果、分页 |
| 歌单/专辑/歌手 | 头部展开/收起、歌曲行、选中、悬停、菜单与滚动 |
| 播放 | 未播放、播放/暂停、进度拖动、音量、队列、音质菜单与错误 |
| 全屏播放器 | 封面、普通/逐字歌词、翻译、背景、歌词定位与模式切换 |
| 设置及弹层 | 明暗主题、主题色、表单、弹窗、抽屉、消息与确认框 |
| 本地与流媒体 | 初次配置、扫描/连接中、空库、有数据、失败与恢复 |

先固定 `1440×1000` 作为已观察页面的桌面基线，再补充 `1280×800` 和窄屏；在原项目实际断点两侧采样，不能根据注释猜测断点。原 [useMobile.ts](../reference/SPlayer/src/composables/useMobile.ts) 同时含多组尺寸条件，需结合实际页面样式核对。

已有可从 [AppLayout.vue](../reference/SPlayer/src/layout/AppLayout.vue) 核对的起始尺寸：展开侧栏宽 `240px`、折叠宽 `64px`，显示底栏时侧栏高度扣除 `80px`；主内容横向内边距在移动与其他模式分别为 `16px` / `24px`。这些是样式盘点的起点，最终仍以具体状态的实际渲染为准，不用几个尺寸替代完整测量。

### 6.2 稳定且可信的比较

两套应用使用同一组脱敏、固定的封面、文本、时长、计数和时间数据，避免远端推荐更新造成伪差异。固定字体和主题，等待字体与图片就绪；非动效截图暂停动画。首次协议弹窗单独覆盖，普通页面截图使用隔离的测试状态，不能为了截图修改用户实际协议记录。

使用 Playwright 截图比较和人工叠图检查。官方说明截图会受系统、浏览器和运行环境影响，因此同一套基线须在固定环境生成与验证。阈值先用重复采集的噪声校准；已确认固定区域以零差异为目标，对字体抗锯齿等噪声逐项记录例外，不通过放宽全局容差掩盖布局偏移。见 [Playwright 视觉比较](https://playwright.dev/docs/test-snapshots)。

动态背景和歌词动画另设时间点或可重复的时间轴检查；暂停动画后的静态图不能证明动效一致。基线更新必须说明原项目变化或已确认差异，不能把新实现的偏差直接“更新通过”。

## 7. 分阶段路线

阶段按退出条件推进，不给未经验证的日历工期。以下顺序以“先证明原样式和独立播放可以共存”为原则。

### 阶段 0：固定参照与重写范围

交付：页面/状态清单、原项目视觉基线、资源来源清单、桌面壳验证结果、首发功能范围表。

- 核对参考提交与当前运行服务，采集未登录、已登录、首启协议和播放器主要状态。
- 按模板盘点页面，不把源码存在误当成运行正常；每个条目标明“源码确认 / 运行确认 / 待验证”。
- 清点 Naive UI 覆盖、动态颜色、图标、默认图片、字体、歌词库及其依赖来源；复用时记录原项目许可与署名，品牌与文案单独核对，不直接以 Sonora 名义承接 SPlayer 的承诺。许可证文本见 [LICENSE](../reference/SPlayer/LICENSE)。
- 用同一个外壳页和一段本地音频验证候选桌面方案，记录样式偏差、播放能力和打包障碍；若无额外产品目标，优先推进 Electron。

退出条件：原样式有可重复参照；首发平台和第一条真实业务链路已明确；阻塞项有实验结论。

### 阶段 1：独立工程与完整视觉外壳

交付：Sonora 自身可启动的工程、主题层、布局、导航、卡片/列表、菜单、弹层、底部和全屏播放器的展示层，以及视觉比较工具。

- 使用 fixture 驱动 ViewModel，先覆盖首页、列表详情、搜索和播放器四类核心模板。
- 恢复原尺寸、主题规则、图标与组件覆盖；不为了方便改换 UI 库或页面布局。
- 展示层不得导入网易 API、Cookie 工具、旧项目 Store 或平台 DTO。
- 建立类型检查、格式检查和最小视觉检查；原项目通过只读参照参与对比，不成为运行时依赖。

退出条件：断网、无账号也能启动；核心模板的基线对照通过；fixture 能切换登录、空态、错误与播放状态。其余页面列出视觉欠账，不宣称全站已还原。

### 阶段 2：真实播放闭环与自研服务契约

交付：可播放的受控音频样本、队列、基本歌词、喜爱、历史、设置、重启恢复，以及自研音乐服务的客户端契约草案。本地文件是验证播放器独立性的建议入口，不据此决定首发产品必须包含完整本地曲库。

- 第一条链路：选取有使用权限的本地文件 → 读取元数据 → 入队 → 播放/暂停/拖动/切歌 → 显示歌词 → 重启恢复。
- 先接一个满足目标格式的音频引擎，验证 MP3、FLAC、AAC、损坏文件、无封面/无标签和无歌词；实际可支持格式以目标平台实验为准。
- 建立请求取消、状态转换、队列身份、播放模式和持久化规则；基础状态正确后再接高级音效。
- 浏览器文件选择与桌面目录扫描分别实现，不把 Web 环境缺少目录权限解释为整个功能失败。
- 确认自研服务所在仓库与现状，共同定义媒体 ID、分页、搜索、歌单、歌词、播放资源、认证、错误和版本约定；未实现部分使用固定 fixture 验证客户端，不冒充真实联调。

退出条件：无需网易代码或请求即可完成整条链路；真实音频可听且事件与界面一致；快速切歌、播放中暂停、队列编辑和重启不会串状态或丢数据；自研服务联调所需的最小契约明确。

### 阶段 3：自研音乐服务接入与联调

交付：自研服务会话管理、搜索、歌单/专辑/歌曲详情、可播放资源解析、用户喜爱和基础个人歌单。服务端能力需与客户端配套交付；具体接口以双方确认的契约为准。

- 先完成只读浏览和播放，再做收藏、歌单编辑等远端写入。
- 实现自研服务客户端，不引入网易 API 包、网易响应格式或 Cookie 登录机制。
- 明确元数据与音频传输契约：资源有效期、鉴权方式、Range/定位、必要请求头、缓存和错误响应；真实支持的行为通过联调验证。
- 验证会话有效、无会话、过期、账号切换、无播放权限、地址过期和来源端错误。
- 解析接口成功不等于实际能播放：需要验证真实资源传输、跳转、必要请求头以及目标桌面环境。
- 联网结果做真实自研服务契约验证；离线 fixture 只证明映射和界面状态。测试凭据在运行时注入，不作为公开测试材料。

退出条件：在真实自研服务上完成搜索 → 详情 → 播放和歌单写入 → 重新读取验证；登录失效、资源过期和服务不可达均有明确状态；服务端数据与本地缓存区分清楚；播放器核心可以使用受控样本独立验证。

### 阶段 4：形成可日常使用的首版

交付：确认范围内的首页/发现、搜索各类型、歌单/专辑/歌手、收藏/历史、本地音乐、设置和播放器。

- 补齐页面模板的真实数据与行为，对每个页面关闭视觉欠账。
- 接上目标系统的媒体键、系统媒体信息、托盘、窗口状态和全局快捷键；桌面歌词若为首发必需则在本阶段落地。
- 验证大列表滚动、连续播放、睡眠唤醒、网络中断、资源释放及数据库升级。
- 核对浏览器预览与打包产物分别可用；只对明确支持的系统发布。

退出条件：首发范围表全部有功能证据和视觉证据，数据升级有恢复办法，已知缺陷与支持限制有记录。

### 阶段 5：高级能力

候选功能按需求逐项排期，不作为阶段 1–3 的隐含承诺：

- 原项目的 Navidrome / Subsonic / OpenSubsonic、Jellyfin、Emby 支持仅作为调研背景，不纳入当前接入计划；当前音乐服务方向为自研服务。
- 云盘、下载管理、评论、播客、电台、MV、歌曲百科和 Last.fm。
- mpv / FFmpeg 引擎、均衡器、输出设备、ReplayGain、交叉淡化、Automix、频谱、桌面/任务栏歌词及外部媒体集成。
- 设置和歌单的显式导入工具；不默认兼容 SPlayer 全部内部存储格式，不自动读取原应用账号。

每项能力进入实施前都要补充范围、依赖、错误状态和原样式验收；已出现的占位入口在发布前明确处理，避免形成看似可用却没有行为的界面。

## 8. 验证与风险控制

| 风险 | 最早处理阶段 | 必须提供的证据 |
| --- | --- | --- |
| 外观相似但细节逐步漂移 | 0–1 | 原项目固定参考图、同数据对照、偏差记录 |
| 旧平台依赖残留 | 1–3 | 依赖约束及网络检查；Sonora 运行路径不含网易包、认证或请求 |
| 自研服务契约尚未落地或发生漂移 | 2–3 | 客户端/服务端确认的契约、固定 fixture、真实服务联调及版本兼容检查 |
| 异步切歌串状态 | 2 | 可控制响应先后顺序的测试；真实引擎切歌验证 |
| 远端鉴权/音源变化 | 3 | 自有账号的真实契约及实际播放验证；失败分类 |
| 音频格式或原生依赖无法打包 | 0、2、4 | 目标平台样本与实际安装包测试 |
| 数据和队列恢复错误 | 2、4 | 真实存储的重启、迁移、失败恢复测试 |
| 大列表、歌词和背景耗资源 | 1、4 | 固定数据规模的滚动/播放测量，持续运行记录 |
| 账号凭据泄漏 | 3 | 网络与日志脱敏检查、隔离的测试会话 |

单元测试重点放在状态机、队列、ID、DTO 转换、歌词时间和错误规则；存储使用真实数据库验证关键事务；端到端覆盖完整用户链路。视觉、真实音频和平台集成分别提供证据，不用某一类测试代替其他类别。

性能先建立基线：记录冷启动、搜索响应、首音延迟、大列表滚动、持续播放内存与 CPU。阶段 0–2 获得目标硬件上的实测后再设预算，不在没有测量时写“比原项目快”或虚构指标。

## 10. 实施前仍需明确的产品选择
